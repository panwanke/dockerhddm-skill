# Version history

## 0.2.5 — 2026-07-25

- Added a **Sanity checks & troubleshooting** section to `docker-runtime.md`,
  covering image/daemon verification (`docker images` / `docker info` /
  `hello-world`), container-liveness checks (`docker ps` / `docker logs`), and a
  failure-mode table for **each mode**: Jupyter won't open / can't connect
  (missing `-p`, token truncation, port conflict, wrong command, missing `-it`,
  wrong mount) and Bash can't see/read/run files (missing `-v`, wrong `-w`,
  permission denied, bind-mount exec restriction with the `/tmp` copy fix, CRLF
  line endings, `--rm` file loss, wrong image tag). Version bumped to 0.2.5.

## 0.2.4 — 2026-07-25

- Expanded `docker-runtime.md` with a **Launch configurations** matrix:
  `--cpus` core limit, single/multiple `-v` mounts (work + data), `-w` working
  dir, custom `-p` host ports, interactive `bash` vs `bash -lc '...'` batch runs,
  a cheap `--cpus=1` write-permission preflight, the `/tmp` bind-mount execution
  tip, and optional Docker daemon-permission (`usermod -aG docker`) notes.
- Added a **Two usage modes** section to `docker-runtime.md`: Mode 1 Jupyter
  (launch `jupyter notebook`, connect via the token URL printed in the logs,
  create a notebook) vs Mode 2 Bash (enter `bash`, write/run plain `.py` scripts),
  with a when-to-use table. Authored Jupyter kernel-connection steps from scratch
  (token/URL + port-swap), since references previously only showed the run command.
- All personal absolute paths from the source project docs are parameterized to
  `$PWD` / `$DATA_DIR`; only image-internal paths
  (`/home/jovyan/work`, `/home/jovyan/work/data`, `/tmp`) remain.
- `SKILL.md` runtime step 3 now points to the launch-config and two-modes
  sections; version bumped to 0.2.4.

## 0.2.3 — 2026-07-25

- Made `env.json` a **required, project-local** config (generated by
  `init_project.py`); it never lives in a global directory. Holds `image_tag`,
  `mount`, optional `dockerhddm_repo`, and `default_mode`.
- `init_project.py` now writes `<project>/env.json` from `assets/env.example.json`
  and accepts `--image-tag`; bootstraps `env.json` for an existing project that
  lacks it instead of refusing.
- Added multi-version support: `1.0.1`, `0.8`, `latest` are allowed via
  `image_tag`, but all guidance is anchored to `1.1.0` (authority warning added
  to `SKILL.md`, `docker-runtime.md`, and `inspect_environment.py`).
- `docker-runtime.md` rewritten with a version-policy/authority section and a
  supported-tags table.
- Redacted the truncated Jupyter token in `pan-2025-dockerhddm.md`; aligned
  `dockerHDDM_Workflow.md` to the `1.1.0` tag.
